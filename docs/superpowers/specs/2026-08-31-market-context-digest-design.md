# 종가표 / 주요 일정 / 관심종목 뉴스 설계

> 대화로 확정된 내용 정리. 브레인스토밍 결과물, 구현 계획은 별도 문서(writing-plans).

## 0. 배경 / 왜 이 기능인가

사용자 요청은 원래 "종가표 + 일정 + 뉴스를 텔레그램으로 정해진 시간에 발송"이었다. 브레인스토밍 중 텔레그램/스케줄 발송 부분은 **로컬퍼스트 원칙(서버가 유저별 워치리스트를 모른다 §2-3)과 정면 충돌**한다는 게 확인됐고 — 개인화 발송을 하려면 서버가 "이 텔레그램 chat_id는 어떤 종목을 보는가"를 저장해야 하는데, 이건 이 앱이 지금까지 지켜온 "계정 없음, 서버는 개인 데이터 없음" 구조를 깨는 첫 사례가 된다. 사용자가 이 부분을 스코프에서 빼기로 결정해서, **알림/발송 채널은 이번 스펙에서 제외**하고 인앱 화면 3곳으로 대체한다.

또한 요청에 "미국 종목"이 반복 등장하는데, 지금 앱은 KR 전용 구조(`stocks.json` 3,982개 KRX 종목만, DART 공시 파이프라인도 KR 전용)라 워치리스트 자체를 한/미 혼용으로 확장하는 게 이번 스펙의 전제 조건이 된다.

## 1. 원칙 / 제약 (기존 설계 원칙 상속 + 이번에 정리된 것)

- 로컬퍼스트 유지 — 서버는 여전히 "누가 뭘 관심 등록했는지" 모른다. 계정/텔레그램/스케줄 발송 없음.
- 실시간 시세 없음 — 전일 종가(T+1)만. 목표주가/적정가 계산 없음 (설계문서 §9 절대금지 상속).
- 뉴스는 헤드라인+링크만 — 원문 무단 전재 금지 (설계문서 §9 상속). 클릭하면 원문 사이트로 이동.
- **API 호출 위치 원칙** (이번 대화에서 새로 정리됨): 데이터가 "키 1개당 하루 호출 한도가 고정된 API"에 의존하면(DART가 대표 사례) — 유저 수가 늘어도 호출량이 늘지 않도록 **서버가 하루 1회만 배치로 긁어 정적 JSON 발행 → 클라이언트가 로컬 워치리스트로 필터링**하는 기존 패턴을 쓴다. 반대로 데이터가 진짜 개인화돼 있고(내 워치리스트 기준) 상대가 공개 무인증 피드라 다수 동시 호출을 감당할 수 있으면(뉴스가 대표 사례) 클라이언트가 그때그때 직접 호출한다. "유저 기기를 최대한 활용한다"는 이 필터링·렌더링·개인화 계산이 전부 클라이언트에서 일어난다는 뜻이지, 쿼터 고정 API를 유저마다 직접 때리게 한다는 뜻이 아니다.

## 2. 워치리스트 한/미 확장 (선행 작업)

`src/lib/watchlistDb.ts`의 `WatchlistItem`에 `market: 'KR' | 'US'` 필드 추가.

- 기존 레코드는 `market` 필드가 없음 → 읽을 때 `item.market ?? 'KR'`로 기본값 처리 (마이그레이션 스크립트 불필요, IndexedDB 스키마 버전업도 불필요 — 필드 추가는 기존 레코드를 깨지 않는다).
- `addToWatchlist(ticker, companyName, market)`로 시그니처 확장.
- WatchlistScreen의 종목 검색은 지금 `stocks.json`(KR) 하나만 보는데, 신규 `us-stocks.json`도 함께 검색하도록 확장. 검색 결과에 KR/US 배지 표시.

**US 종목 유니버스**: SEC가 공식 제공하는 `https://www.sec.gov/files/company_tickers.json` 사용 (무료, 키 불필요, 공식 데이터). 기존 `scripts/generate-stock-list.mjs`와 같은 패턴으로 `scripts/generate-us-stock-list.mjs` 신규 작성 → `public/data/us-stocks.json` 발행. 갱신 빈도는 KR과 동일하게 가끔 수동 실행(상장/폐지가 매일 바뀌는 게 아니므로 cron 불필요, 필요시 나중에 추가).

## 3. 기능 1 — 종가표 (MY STOCK RADAR 화면 확장)

새 탭을 만들지 않고 기존 MY STOCK RADAR(WatchlistScreen) 목록에 종목별 전일 종가·등락을 같이 표시한다.

- **KR 소스**: 공공데이터포털 "금융위원회_주식시세정보" API (이미 검증된 소스, [[kstock_price_data_source]] 메모 참고). 종목코드+일자로 조회.
- **US 소스**: 미확정 — 구현 전 스파이크 필요. 후보: Stooq(무료, 키 불필요, ToS 불명확), Twelve Data(무료 티어 800req/일), Financial Modeling Prep(무료 티어). 상업적 재배포 허용 여부와 무료 한도를 확인 후 확정.
- **방식**: 서버 배치(1일 1회, 기존 GitHub Actions cron 패턴) — KR 3,982종목 + US 유니버스 전체 종가를 `public/data/prices.json`으로 발행. 클라이언트는 이 파일에서 로컬 워치리스트 티커만 골라 표시. (API 호출 위치 원칙: 쿼터 고정 API 전제)
- **표시**: 종목명 옆에 `전일종가 / 등락률` (KR은 원화, US는 달러 그대로, 통화 변환 안 함 — 환율은 별도 스코프).

## 4. 기능 2 — 주요 일정 (EVENTS 화면 확장)

기존 EVENTS(EventCalendarScreen)의 "주주총회 관련 공시" 섹션 옆에 섹션 2개 추가:

**(a) 주요 경제지표 발표 일정** (개인화 없음, 전체 공통):
- 미국: CPI, 소매판매, 고용지표(비농업고용) — BLS(bls.gov)가 매년 공식 발표일정을 미리 공개함. FOMC 회의 일정도 연준이 연 단위로 고정 공개.
- 한국: 한국은행 금통위 회의 일정 (한국은행이 연 단위로 고정 공개) — KR 서비스이니 US만 있는 것보다 대칭성 있게 포함.
- **구현**: 위 소스들은 전부 "연 1회 발표되는 고정 일정표"라 실시간 API 연동보다 **연 1회 수동 갱신하는 작은 정적 JSON**(`public/data/econ-calendar.json`)이 더 단순하고 안정적이다 (설계원칙 "매일 수작업 없음"은 어기지 않음 — 연 1회는 매일이 아님). 나중에 FRED API 등으로 자동화할 수도 있으나 MVP는 정적 파일로 시작.
- 오늘 기준 앞으로 7일 내 일정만 노출.

**(b) 관심종목 실적 발표 일정**:
- KR: 기존 `scripts/fetch-facts.mjs`가 지금 카테고리 I/B/D만 가져오는데, 정기공시(A) 카테고리를 추가해서 실적 관련 공시(잠정실적, 사업/분기보고서)를 걸러낸다. **기존 파이프라인 확장일 뿐, 새 인프라·새 키 노출 없음.**
- US: 미확정 — 구현 전 스파이크 필요. 후보: Finnhub 무료 티어(실적 캘린더 포함), Financial Modeling Prep. ToS상 상업적 재배포/저장 허용 여부 확인.

**(c) 13F 기관 보유변동** (분기 이벤트로 이 화면에 포함):
- SEC Form 13F — 운용자산 1억달러 이상 기관의 분기별 보유종목·비중변동 공시. SEC가 공식/무료로 원본 데이터셋 제공(`sec.gov/data-research/sec-markets-data/form-13f-data-sets`). KR의 "5%룰 대량보유·임원지분변동" 공시 추적과 성격이 같은 미국판 — 이 앱의 공시 기반 정체성에 부합.
- 원본이 CUSIP 기준 통짜 데이터셋(수백MB)이라 브라우저 파싱은 무리. **분기 1회(연 4회) GitHub Actions 배치**로 다운로드→파싱→CUSIP-티커 매핑→전분기 대비 변동 계산 → `public/data/13f-changes.json` 발행. 클라이언트는 이 파일을 로컬 워치리스트로 필터링.
- 표시: "OO기관, 전분기 대비 보유비중 +X%p" 형태의 사실 나열. 매수/매도 권유로 읽히지 않게 문구 주의 (기존 팩트체크 화면 톤 유지).

**빈 상태**: 위 세 섹션 모두 오늘 기준 해당 일정이 없으면 "주요 일정 없음"을 그대로 노출 (요청사항 그대로).

## 5. 기능 3 — 관심종목 뉴스 (CompanyDetailScreen 확장)

- 종목 상세 화면 진입 시, 그 종목명으로 뉴스 헤드라인만 조회해 리스트로 보여준다. 클릭 시 원문 링크로 이동 (본문 텍스트 저장/표시 없음 — 무단전재 금지 원칙).
- **소스**: Google News RSS (`news.google.com/rss/search?q=...&hl=ko&gl=KR` / `hl=en&gl=US`). 공식 공개 피드, 키 불필요. KR/US 동일 방식이라 소스 하나로 통일.
- **호출 위치**: 클라이언트 직접 호출 (진짜 개인화된 요청이고, 화면 열 때만 그 종목 하나 조회하는 저빈도 호출이라 서버 배치 불필요). **구현 전 스파이크 필요**: 브라우저에서 CORS 없이 직접 fetch 가능한지 확인 — 막히면 응답 저장 없는 얇은 서버리스 프록시(Vercel function, 단순 릴레이) 하나만 예외적으로 둔다.
- RSS는 XML이라 클라이언트에서 파싱 필요 (`DOMParser` 내장 API로 충분, 별도 라이브러리 불필요).

## 6. 스코프 밖 (명시적으로 안 함)

- 텔레그램/이메일/푸시 등 예약 발송 — 로컬퍼스트 원칙과 충돌, 나중에 "계정을 도입할 것인가"를 별도로 다시 논의.
- 환율 변환 (US 종가는 달러 그대로 표시).
- 뉴스 감정분석/요약 (헤드라인+링크만, AI 가공 없음).
- 실시간 시세, 목표주가/적정가.

## 7. 구현 전 확인해야 할 스파이크 (writing-plans 진입 전 또는 1단계로)

1. US 종가 API 확정 (무료 한도 + 상업적 재배포 ToS)
2. US 실적캘린더 API 확정 (동일 기준)
3. Google News RSS 브라우저 직접 fetch 가능 여부 (CORS)
4. SEC 13F 데이터셋 실제 포맷 확인 + CUSIP→티커 매핑 방법

## 8. 테스트

- 가격/일정/13F 파싱 로직은 순수 함수로 분리해 각각 최소 1개 케이스 검증 (기존 `*.selfcheck.ts` 패턴 재사용).
- 워치리스트 market 필드 기본값 처리(`undefined` → `'KR'`) 케이스 검증.
- UI는 로컬 개발 서버로 KR/US 혼합 워치리스트 기준 수동 확인.
