# 주식가계부 (Stock Ledger) 설계

> 대화로 확정된 내용 정리. 브레인스토밍 결과물, 구현 계획은 별도 문서(writing-plans).

## 0. 배경 / 왜 이 기능인가

원래 "펀더멘털 스크리닝"을 검토하다가, 계산된 "적정가"를 현재가와 비교해 보여주는 안이 설계문서 9번("절대 금지: 목표주가 제공")과 정면 충돌하고, 한국 자본시장법상 무인가 투자자문업 소지까지 있어 보류됨. 대신 **사용자 본인이 입력한 매수가 대비 손익을 계산**해주는 주식가계부는 "판단 제시"가 아니라 "본인 데이터 계산"이라 이 문제에 걸리지 않고, 앱의 핵심 문장("내 투자에 오늘 무슨 일이 생겼는가?")에도 스크리닝보다 더 직접적으로 부합함.

**스크리닝(지표 나열형, 목표가 비교 없는 버전)은 이 스펙의 범위가 아니고, 별도로 파킹된 상태.** 나중에 다시 꺼내려면 이 문서를 참조.

## 1. 원칙 / 제약 (기존 설계 원칙 상속)

- 브로커 API 자동연동 없음 — 100% 수동 입력 (설계문서 8번에서 "브로커 연동 필요"로 기각됐던 매매일지 기능을 수동입력으로 우회)
- 로컬퍼스트 — IndexedDB에만 저장, 서버 없음 (§2-3 상속)
- 양도소득세 계산 없음 — 국내 개인투자자는 대주주 요건(코스피 지분 1%·시총 50억 등) 미만이면 비과세라 일반 사용자에겐 해당 없음. 대주주 여부 판별 자체가 스코프 밖.
- 목표주가/적정가 계산·제시 없음 — 사용자가 입력한 실제 매수가만 사용.
- 실시간 시세 없음 — 보유종목 현재가(평가손익 계산용)는 워치리스트 스코프의 종가 데이터로, 일 1회 배치 갱신(기존 GitHub Actions 패턴 재사용).

## 2. 데이터 모델

`src/lib/db.ts`의 기존 단일 IndexedDB 커넥션에 스토어 추가 (DB_VERSION 5로 증가):

```
trades (매매 원장 - append-only, 수정은 새 레코드로)
  id, ticker, type: 'buy'|'sell', date, quantity, pricePerShare, fee

dividends (배당 기록)
  id, ticker, date, grossAmount
```

평단가/보유수량/실현손익/미실현손익은 **저장하지 않고 trades에서 매번 파생 계산** — 중복 상태로 인한 불일치를 피하기 위함(다른 스토어처럼 값 자체를 저장하지 않음).

## 3. 계산 로직

- **평단가 (이동평균법)**: `새평단가 = (기존평단가×기존수량 + 신규매입가×신규수량) / (기존수량+신규수량)` — 매도는 평단가에 영향 없음, 수량만 감소
- **실현손익** (매도 시점): `매도금액 − (매도시점 평단가×매도수량) − 매매수수료 − 증권거래세(약 0.15~0.18%, 매도 시에만)`
- **미실현손익** (보유중): `(현재가 − 평단가) × 보유수량` — 현재가는 워치리스트용 종가 데이터 재사용. **선행 의존성**: 공공데이터포털 "금융위원회_주식시세정보" API 연동(종목코드+일자 조회, T+1)이 아직 미구현 — 이 스펙 구현 전에 먼저 붙여야 함. 그 전까지는 미실현손익 없이 매입원가/실현손익만 표시하는 것도 가능(현재가 의존 부분만 분리 가능한 구조로 설계).
- **배당**: `dividends`에 세전 기록, 표시 시 기존 `src/lib/tax.ts`의 `afterTax()`(15.4% 원천징수) 재사용해 세전/세후 토글

## 4. UI

새 화면 `src/components/LedgerScreen.tsx` (기존 Screen/Section 패턴 재사용):
- 종목별 보유 리스트: 평단가, 보유수량, 평가손익(%, 금액)
- 매수/매도 입력 폼: 종목(워치리스트에서 선택), 일자, 수량, 단가, 수수료
- 배당 탭: 종목별 배당 기록 + 세전/세후 토글
- 전체 요약: 총 매입원가 / 총 평가액 / 총 손익

## 5. 백업

`src/lib/ledgerExport.ts` (신규, 작음): trades + dividends를 JSON으로 export/import하는 순수 함수 2개. 클라우드 동기화는 없음 — 파일 하나로 기기 이전/백업, 기존 "내보내기/가져오기(JSON) 수동 백업" 계획(§2-3) 최초 구현.

## 6. 스코프 밖 (명시적으로 안 함)

- 브로커 자동연동
- 양도소득세 계산 (근거: 3번 원칙)
- 목표가/적정가 계산 (근거: 1번 원칙)
- 클라우드 자동 동기화
- 배당락일 자동 draft 생성 (아이디어는 있었으나 MVP에서 제외, 나중에 확장 가능)

## 7. 테스트

계산 로직(`src/lib/ledger.ts`에 순수 함수로 분리 예정)에 대해 이동평균 평단가, 실현손익, 미실현손익 각각 최소 1개 케이스 검증. UI는 로컬 개발 서버로 수동 확인.
